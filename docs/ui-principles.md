# 界面与交互原则

Web 与共享 thread UI 的统一规则。新增或修改界面时先对照这里；某处必须例外时，在代码注释里写明原因。主题包只改外观（配色、图标、小控件），不改下面任何语义与行为，见 [theme packs](theme-packs.md)。
  - 例外：Relay 管理后台（`/relay-admin`，含其登录页）始终显示经典主题，只跟随浅色或深色设置，不套用浏览器选中的主题包；离开后台即恢复所选主题包，存储的选择不变（`pinTheme`，`RelayAdminPage.tsx`）。原因：后台是运维工具，图表、表格和状态标识按经典主题绘制，一种固定外观便于不同管理员对照截图和说明。

## 1. 一类操作，一种做法

同一种操作在所有位置用同一个入口形态、同一个图标、同一句文案、同一种反馈。用户在一处学会的，换到另一处、另一个主题、另一种设备都成立。

- 例外：桌面宿主 surface 和已登录的 PC 浏览器在既有侧栏上方增加跨设备的「活动」分区，并在 rail 的地图入口上显示琥珀色等待数（审批或输入，不用管理员注册队列的红色）。原因：两者持续持有同一个账号级活动索引；原生客户端额外供系统通知、托盘与桌宠共用，浏览器不启用这些宿主行为。活动与桌宠使用同一活动来源和顺序，沿用 StatusMark 与线程菜单（`src/desktop/ActivitySection.tsx`）。
- 例外：Electron 桌面客户端自带的首次连接、偏好设置、快捷窗口和桌宠是本地窗口，不加载远端 React 组件；它们用本地 DOM 实现与共享组件相同的焦点、键盘、ErrorMark 与自绘滚动条行为，状态标识的 SVG 来自客户端仓库的 `desktop/src/shared/statusMarks.ts` 并与本节 §6 同步，文案跟随网页当前语言。原因：这些隔离窗口只接收脱敏的活动快照，必须离线可用，不能引入远端页面运行时。

- 例外：Relay 的手机登录同意页在 API origin 以无脚本 HTML 显示，沿用 Classic 登录卡片和系统浅色/深色，不读取另一 Web origin 的主题包。原因：第三方认证的系统浏览器可能没有 Web 页的存储和运行时；安全警告与「继续／取消」必须在独立 API 部署下直接可用，不能依赖远端 JS 或跨 origin 主题状态（`crates/relay/src/mobile_consent.html`）。

- 例外：有左侧 rail 的 Relay 页面在底部用 32px 账号头像（40px 点击区域）代替设置齿轮，账号菜单向上打开；手机普通模式把头像放在顶栏通知铃铛之后，菜单向下并右对齐，单手模式头像位于底部，菜单按锚点空间向上打开；本地模式没有账号，保留齿轮。原因：账号与设置共用固定入口，手机顶栏和底部 dock 各自保持不拥挤，菜单始终留在安全区内。

## 2. 复制

- 所有复制都用同一个复制按钮组件：双页图标；成功时图标变为对勾约 1.5 秒，并通过 `role=status` 宣告「已复制」；失败时图标变为红色警示，并就地显示「复制失败」，不只写在 title 里。
- 内容块（消息、代码、命令输出）的复制在桌面悬停或聚焦时出现，在触屏轻点内容块时出现。工具栏型内容（图表）可以常显。
- 显示出来的路径一律是「路径条」：等宽字体，中间省略，保留首尾段，末尾带复制按钮；轻点路径条以卡片显示完整值。路径不能只是纯文本，完整值也不能只放在 title 里。
- 复制的内容就是标签所说的内容：「复制路径」复制工作区相对路径，需要绝对路径时明确写「复制绝对路径」。
- 菜单里的复制项在自己身上反馈：图标变对勾、文字变「已复制」，约 0.7 秒后菜单关闭；失败时这一项变红写「复制失败」，菜单不关。不在菜单底部另起一行提示。

## 3. 菜单

- 有操作的对象（线程、文件、终端、文件链接）都有同一个菜单，三种打开方式等价：⋯ 按钮（触屏常显，桌面在悬停或聚焦时显示）、桌面右键、触屏长按。
  - 例外：资源管理器的文件行，触屏长按显示完整文件名（松手消失），桌面悬停在被截断的名字上也显示它；那里的菜单用 ⋯（触屏常显）、右键或菜单键打开。原因：文件名常被截断，长按看全名比再开一次菜单更常用（`ExplorerNameBubble`）。
- 触屏上，点菜单、列表、面板里的项，绝不会穿透到它下面的控件。iOS（所有 iOS 浏览器都是 WebKit）点按钮不给它焦点，点击又在抬手后才生成：靠失焦关闭、或在按下/抬起时就关闭的弹出层，点击会落到下面。全局守卫 `installTouchTapGuard`（`apps/supervisor-web/src/lib/touchTapGuard.ts`）处理这两种情况：按下弹出层里的控件时先给它焦点（正在输入时除外，键盘不收起）；按下的元素在点击到来前已离开页面、点击又落到别处时，丢弃这次点击。新菜单不必各自处理，但仍不要在失焦时关闭。
- 终端的选字与复制控件为保留选区而阻止默认聚焦时，用 `mousedown`，不取消触屏 `pointerdown`：WebKit 会连随后那次点击也一起丢弃。
- 菜单是 `role=menu`。打开时聚焦第一项；上下方向键移动，Home/End 跳到首尾；Esc 关闭并把焦点还给触发器。
- 浮动菜单渲染到页面根部，不能让工具栏的裁剪或层叠影响点击区域。一次点击或轻点完成前，不因失焦卸载菜单；通过选择菜单项、点外部或键盘操作关闭。
- 锚定在内容上的菜单和浮层，要么随锚点移动，要么在锚点离开视野时关闭，不留在原屏幕坐标上。
- 浏览器工具栏、缩放或软键盘只改变可视视口时，也要重新计算浮层位置和可用高度。
- 手机线程页的左边缘约 28 CSS px 属于系统或浏览器返回手势：从这里开始的触摸不启动侧栏拖动，也不 `preventDefault`。从更里面开始的主要水平右拖才打开侧栏；代码块、表格、标签条、线程地图和其他横向滚动区域继续保留自己的滚动手势。Android 系统手势区、iOS 壳和移动 Safari 遵守同一条边界规则。

## 4. 二级窗口

- 头像菜单与其他顶层菜单、手机面板互斥：打开头像菜单先关闭已有顶层浮层，打开其他菜单或手机面板也关闭头像菜单。面板内的普通控件菜单仍属于该面板。

- 线程工作台分三列：左边是导航（rail、工作区与线程列表），中间是对话、输入和底部终端，右边是查看当前线程的停靠栏（文件、Git、隔离环境，同一时间一个）。停靠栏不是二级窗口：没有遮罩、不困住焦点，对话照常点击、滚动和输入；它是带名称的 `complementary` 区域，标题下写明所属线程，切换线程时内容跟随新线程，不留旧线程的数据。rail 的入口按下即打开或关闭对应视图；读者打开时焦点进入停靠栏，关闭后回到打开它的控件；停靠栏内按 Esc 关闭它，对话里的 Esc 不受影响。宽度与文件共用、可拖动或用方向键调整，只记住开着哪个视图和宽度。窗口窄到放不下 280px 的对话加 360px 的停靠栏时（手机），停靠栏占满工作区，返回或 × 关闭；手机单手 dock 从「更多操作」打开。栏内的二级确认仍用共享确认窗口（`WorkbenchPanels` 的 `inspector`，`components/ThreadInspector.tsx`）。
- 手机（宽度小于 640px）上，二级窗口一律从底部升起：遮罩加模糊，顶部是标题、可选副标题和 ≥40px 的 ×，中间滚动，底部是操作。桌面用居中对话框或锚定浮层。
  - 例外：Relay 管理后台的行详情在桌面是贴右侧的抽屉（`DetailWindow`），手机上仍从底部升起。原因：管理员要一边看详情一边对照表格里的其他行，居中对话框会盖住表格。抽屉同样是模态窗口，遵守下面的焦点规则。
- 二级窗口永远浮在页面之上，渲染到页面根部，不嵌进打开它的工具栏、网格、列表行或面板里，也不挤占它们的空间。
- 打开时焦点进入窗口；模态窗口把 Tab 限制在窗口内；Esc 只关闭最上层；关闭后焦点回到触发器。
- 退出时有未保存的输入，先询问，不静默丢弃。

### 管理后台的表格

Relay 管理后台的每个列表用同一个表格（`AdminTable`，`pages/relayAdmin/table.tsx`）：点击列头按升序、降序、默认顺序循环，列头带小箭头并有 `aria-sort`；拖动列头右边缘调整列宽，双击或在边缘上按 Enter 适应内容，左右方向键微调；「列」菜单显示或隐藏列并可重置。列宽、显示的列和排序按表格存在浏览器里，排序和筛选同时写进 URL。筛选在表格上方排成一行药丸（「状态：在线 ▾」），选项菜单带数量，人员用可搜索的选择器，时间用预设加自定义范围；有筛选时显示「清除筛选」。手机上表格变成列表，排序用一个菜单。凡是列出设备的地方（表格、图表的列表、事件、管理员操作、抽屉），设备名都带上它的主人：设备名打开设备详情，主人名打开此人详情，邮箱作为主人链接的 title 并在此人详情里可见；手机列表行写成「mac · alice」（`DeviceOwnerCell`，`pages/relayAdmin/owners.tsx`）。按时间作图的页面只有顶栏一个时间范围，页面上所有随时间变化的图都跟随它并写进 URL；表示当前状态的卡片标「当前」。侧栏可以收起成图标栏，名称仍是按钮的可访问名称，悬停或键盘聚焦时显示在旁边；选择存在浏览器里。导航和子标签上的数字分两种：等管理员处理的事项（待审批的注册）是红底数字，读屏器读出它是什么（「3 个注册待审批」），没有待办就不显示；单纯的总数（设备、分享）是灰底。只有真正要管理员动手的队列才用红色。

## 5. 展开与折叠

- 引用：在对话里选中某条消息中的文字后，出现「引用」小药丸（手机固定在输入框上方，鼠标在选区末尾下方），只在有选区时出现。浏览器不允许网页往系统选字菜单里加项，所以这是自己的按钮，不是系统菜单的一项。引用在输入框里和已发送的消息里都是带编号的小标签，点开是引用卡片（出处、原文、预览原处、移除）。
- 可展开的行，在行首放一个 chevron：收起时朝右，展开时朝下。类型符号（`$`、`±`、文件图标等）只表示类型，放在 chevron 之后。
- 例外：手机线程地图的 `+N` 是容器的缩放入口，不原地展开；每个容器最多一行，不在该行里嵌套另一行。原因：保留嵌套 treemap 的比例与热度；带文字的线程块至少 96×44px，更小的块仅显示图标或色块，可通过菜单里的列表与「转到」使用完整触控目标（共享 UI `threadMap/ThreadMap.tsx`、`phone.ts`）。
- 不设冗余层级：一个层级只有一个子项时，展开父级时子项一并展开。
- 原地展开，不跳动：被点的那一行在屏幕上保持不动。命令输出、终端日志不自动展开。
- 看起来像工作线的行都能展开。一轮结束了却什么都没记录下来（例如 Supervisor 断开前被中断），展开后写明「这一轮没有记录到任何内容」和原因，而不是一条点不开的线。

## 6. 状态语言

线程、轮次和工具的状态在所有位置（标签、侧栏、抽屉、底部面板、分屏选择、线程地图、通知、手机底栏）使用同一组标识，并且都带可访问名称：

| 状态 | 标识 |
| --- | --- |
| 运行中 | 旋转的环（线程地图中为橙色心跳） |
| 等待你（审批或输入） | 琥珀色实心对话气泡（右下带尾巴），静止不动 |
| 已完成、未读 | 实心点（主题的强调色） |
| 已读、空闲 | 空心小圆 |
| 已中断 | 琥珀色实心方块（停止符） |
| 失败 | 红色菱形 |
| 智能体线程运行中（根线程空闲） | 紫色圆环，中心一点，缓慢呼吸 |
| 未知 | 虚线小圆，半透明 |

热度、费用等附加信息不能顶替状态标识。主题包可以换标识的画法，但每个状态必须仍能只凭形状认出来，不能只靠颜色区分；动画只给「运行中」和「智能体线程运行中」。例如终端主题用闪烁的块状光标表示运行中、轮廓块表示智能体线程运行中、短横表示已中断。标签上智能体数量旁的机器人图标，在有智能体线程运行时缓慢渐亮再渐暗；它只是辅助提示，线程状态仍由标识表达。改动任何标识后，在所有主题的浅色和深色下各看一遍。

- 例外：iOS Live Activity / 灵动岛以及 Android 系统持续活动中的运行中标识使用静止圆环，由系统计时文字表示仍在运行，不循环自绘动画。原因：系统活动组件不支持可靠的持续自绘动画，后台更新也不能承担动画时钟；等待你的气泡与失败菱形仍沿用本节形状（Relay 的 `live_activity.rs`，原生资源由客户端维护）。

### 设备连接状态

设备的连接状态不是线程状态，不借用上表的标识。Relay 管理后台用另一组，同样只凭形状就能区分，并且都带文字或可访问名称（`DeviceStateMark`）：

| 状态 | 标识 |
| --- | --- |
| 在线 | 实心圆点，主题成功色（`--status-success-fg`） |
| 离线 | 空心小圆，次要文字色（`--theme-fg-muted`） |
| 频繁重连（1 小时内重连 ≥ 5 次） | 菱形 |

是否受保护（设备证书）是另一维度，用盾牌（勾＝已保护，感叹号＝未保护）加文字，不与连接状态合并。

### 隔离环境状态

隔离环境（Dokploy 容器）的生命周期不是线程状态，不借用线程标识。它用另一组形状，并且总跟着状态文字（`EnvironmentStateMark`，`components/environments/ui.tsx`）：

| 状态 | 标识 |
| --- | --- |
| 运行中 | 实心圆点，主题成功色 |
| 已停止 | 空心小圆 |
| 创建中、启动中、停止中 | 旋转的细环，主题强调色 |
| 失败 | 红色菱形 |
| 已中断 | 琥珀色实心方块 |
| 已销毁、未知 | 虚线小圆，次要文字色 |

隔离申请仍使用线程标识：待你批准是「等待你」气泡，已批准等待空闲和迁移中是运行中的环，迁移失败是红色菱形，其余是空心小圆；批准、等待空闲、迁移、已隔离四步进度只在申请审阅里出现。

### 服务器健康状态

Relay 管理后台「服务器」分区的每个数值有一个健康状态，同样只凭形状就能区分，并且总带文字（`HealthMark`，`ServerPage.tsx`）：

| 状态 | 标识 |
| --- | --- |
| 正常 | 圆中对勾 |
| 偏高（琥珀色） | 三角感叹号 |
| 严重（红色） | 八边形感叹号 |
| 不可用（系统不提供该数值） | 虚线小圆，次要文字色 |

颜色只是附加；阈值在页面上「什么情况会变成琥珀色或红色」里逐项列出。

## 7. 对话与智能体线程

智能体线程从不单独出现。凡是列出它的地方（标签、侧栏、各类底部面板、通知、线程地图），都带上它所属对话的根线程，并折叠在根线程的行下面。计数按对话计。智能体线程的数量只计未关闭（`closedAt` 未设置）的线程；标签、侧栏与地图提示保持一致。菜单保留已关闭的线程，排在未关闭线程后并用次要文字色；全部关闭后隐藏数字，保留原有的机器人入口。

桌面线程地图不另设关注卡片条：等待、失败和未读由瓦片标识与侧栏「活动」表达，活动变化不挤占地图高度。点击瓦片打开线程，在请求面板中审批；瓦片的详情窗口仍可批准或拒绝。

线程地图按工作区算时间和用量，所以有一处例外：在另一个工作区干活的智能体线程，在它干活的工作区里单独成块（它在那里创建的智能体线程折叠在它下面），大块上注明由哪个线程创建。单独打开的智能体线程，在对话上方用一行关系条指回创建它的线程。

## 8. 悬停只是增强

悬停才出现的东西，在触屏上必须能通过轻点触达，在键盘上必须能通过聚焦触达。tooltip 和 title 不承载关键信息；触屏上需要的完整信息，用卡片或底部面板展示。

浮在内容上的操作层（时间、复制）不得盖住它所属内容的状态标识或正文：优先放在内容旁边的空白处（例如右对齐气泡左侧的空白）；没有空白时，才用渐变背景浮在右下角。

## 9. 对齐

同一行里的图标、数字和文字垂直居中对齐；数字与文字共享同一条基线（图标单独居中，不能把数字顶上去）。主题换字体（如等宽字体）后要重新检查对齐。

工作区页在导航标题下用次要文字颜色显示当前设备名；长设备名单行省略，不挤占导航按钮。

- 例外：桌面客户端和已登录 PC 浏览器的工作区页（宽度 ≥640px）使用线程的 rail 与侧栏，去掉页面顶部导航栏；侧栏标题为带 DeviceStateMark 的设备切换菜单，添加工作区、导入会话、线程地图位于侧栏上组。内容标题只保留刷新，Supervisor 折叠行位于列表底部。原因：桌面客户端以侧栏作为主导航，重复顶栏会分散入口。手机、移动宿主和本地浏览器保留现有 Web 布局。桌面内容从标题栏下留 32px，左右和底部 32px；窗口宽度小于 900px 时左右 20px；正文最大 880px 并靠侧栏左对齐（`desktop/WorkspacesFrame.tsx`、`pages/WorkspacesPage.tsx`）。

- 桌面客户端和已登录 PC 浏览器的 rail 在对话、工作区、Devices 和账号设置间保持同一 logo、顺序和纵向位置；无终端的页面保留禁用终端入口，上下文工具位于全局导航之后，不推动公共入口或底部头像。桌面底部统一保留账号入口；设备监控从 Devices 卡片进入，教程从头像菜单进入，避免线程页单独增加底部按钮。

- 桌面客户端和已登录 PC 浏览器的账号设置页也使用上述 rail、侧栏和 32px 内容间距，正文在独立滚动区内；浏览器和手机使用相同设置行，手机堆叠。资料、共享、登录与安全、账户密钥、浏览器和危险操作各用一行，危险操作最后。

- 已登录 PC 浏览器在 Devices、线程和工作区间保留同一个 rail 与侧栏实例；展开、宽度和滚动位置由共享 `PersistentWorkbenchNavigation` 持有，页面只在绘制前更新导航内容。Devices 复用客户端的 `DesktopMapPage`，不加 ProductHeader；浏览器不加窗口控制、更新入口、拖动区域或桌宠。

- 例外：PC 的设备管理统一进入 `/desktop/devices`；手机宽度（小于 640px）的浏览器和移动宿主保留 `/relay-devices` 的原页面，因为手机没有专用设备页。目标按页面加载时的宽度和宿主决定，跨断点调整窗口不触发路由切换；旧 PC 链接仅作保留查询参数的替换跳转。

## 10. 触控尺寸

手机上，可点区域不小于 40×40px（视觉可以更小，用伪元素扩大命中区）；主要操作和底部面板里的行不小于 44px。相邻的危险操作与普通操作之间至少留 8px。

- 例外：模型键下的上下文条和模型文字是同一固定高度内的两个独立按钮，条的命中区仅占底部 8px，不扩展到模型文字上。原因：保持输入工具栏原行高，避免两项命中区互相遮挡；上下文条保留独立键盘焦点和可访问名称。

## 11. 反馈与危险操作

- 每个操作在 100ms 内给出可见反馈。成功就地确认（对勾、状态文字），失败就地给出原因并提供重试。
- 失败原因、不可用原因不以大段文字直接摆在页面上，统一用共享的 `ErrorMark`：出错的位置（或不可用的控件之后）放一个低对比的小感叹号，点开才在气泡里看到原因（有重试时带「重试」）；读屏器仍会读出原因；过去的失败（如失败那一轮的提问）同样用感叹号但不朗读，原始错误以小字附在气泡里。气泡跟着感叹号移动，感叹号离开窗口才关闭。不可用的控件保持原位、置灰、禁用，感叹号紧跟其后（`kind="unavailable"`）。后台自动刷新、轮询的失败不打扰读者：保留上次的结果，只有读者亲自发起的操作失败才出现感叹号。表单里正在输入的字段的校验提示（如「密码太短」）可以保留一行短文字。历史记录（如自动化的执行历史）里每次运行的出错信息是记录内容，照原文列出，不改成感叹号。
  - 例外：登录页上「为什么没登录成功」是卡片顶部的一行可见文字（`AuthNotice` 的 `warning` 或 `info`），不是感叹号：从 Google/GitHub 回来、账号在等管理员批准、注册未通过、账号已停用、Relay 不接受新注册。原因：读者刚从另一个网站回来，或输入的密码是对的，页面上没有别的东西表明发生了什么，藏在按钮旁的感叹号读起来就是「什么都没发生」。密码错误和表单校验仍用感叹号（`AuthUi.tsx`、`lib/signInOutcome.ts`）。
- 对话图片（附件缩略图、内嵌图片和放大预览）共用恢复逻辑：加载失败后重新解析地址，短暂退避后最多自动重试两次；连接恢复时再试。仍失败时显示主题化的图片占位和 `ErrorMark`，在气泡中提供「重试」，不留下浏览器的破图标。已持久化附件首先使用文件地址，不再复用发送前的本地 blob 预览；原生图片加载失败后由页面自己的加密通道读取，显示页面持有的 blob，重试同样走此通道并尝试重新注册 worker。每个已挂载图片最多持有一个恢复 blob，替换或卸载时释放；缩略图失败时才读取原图，原图预览按需加载。worker 重启后向请求所属页面恢复 Relay 配置，不借用其他窗口。最终失败时只探测一次同一地址，诊断日志只含 HTTP 状态、内容类型、路径哈希以及页面是否受 worker 控制、诊断请求是否由 worker 处理；能确定的会话过期、文件不存在或设备离线等原因显示在原有错误气泡中。
- 不可撤销的危险操作（删除、终止仍在运行的进程、覆盖磁盘文件）弹确认对话框：写明对象名称和后果，默认聚焦「取消」，确认按钮为红色。不破坏任何东西、但会新建对象或跳转的确认（如从某一轮分叉）用同一个对话框，确认按钮用主色（`tone: 'primary'`）。可以撤销的移除用「已移除 · 撤销」提示，不弹确认。
- 终端输出里的链接只接受 HTTP/HTTPS，用共享确认窗口显示完整目标。确认后把目标 URL 直接交给浏览器的新窗口入口，供 Web 与原生宿主按各自的正常路径打开；不先开空白窗口再改地址。
- 例外：桌面客户端的更新确认使用已有 `ConfirmDialog` 的主色按钮「更新」，标题为「更新并重启？」；正文先列出会丢失未发送内容的对话标题，并保留附件及未保存文档的数量。原因：这是更新与重启的主操作，丢失内容通过明确文案告知，初始焦点仍在「取消」；所有窗口同意并通过卸载检查后才继续安装（`desktop/prepareUpdate.ts`）。
- 不使用浏览器原生 `confirm()` 或 `alert()`。唯一例外是必须同步作答的离开守卫（有未保存的文件草稿时切换线程或路由），浏览器只接受同步结果。
- 有危险性的入口在外观上就带危险色，不与普通工具按钮同色。
- 要求输入密码或解锁的弹窗必须写明具体原因：缺少浏览器密钥、哪台设备拒绝了哪个请求（方法、路径、错误码）、或哪个操作需要账号密钥，并能复制诊断信息。打开弹窗的代码都要带上原因（`requireUnlock` 的 `cause`、传输状态的 `unlockCause`，显示用 `UnlockCauseNote`），不能只弹一个通用的「请输入密码」。

## 12. 输入

- 表单选择使用共享 `Select`，不新增原生 `<select>`（含 `createElement`）。选项浮层渲染到页面根部，使用 `useMenuKeyboard`，随可视视口定位，并保留标签、禁用、键盘、表单提交、必填和重置语义。Web 与共享 UI 的 `formControlGuard.test.ts` 检查源码。
- 复选框、单选、滑块、数字和日期输入的外观统一由共享 `form-controls.css` 绘制，使用主题 token；保留原生输入、约束和键盘语义。主题只改变外观，不改变控件行为。Electron 本地窗口采用同样的外观与键盘模型。

- 用户逐字输入的内容就是发送的内容。快捷触发（如 `/` 打开工具箱）只能追加界面，不能吞掉字符：后续字符不匹配命令时，原样保留在输入框里。
- 发送按钮的图标和名称表达真实意图，所有主题一致：立即发送、本轮结束后发送（排队）、插话、设定目标各不相同。
- 当前模式（计划、目标）在输入区有持续可见的标识和退出入口，不只在菜单里。
- 输入框收起时隐藏了内容，在首行末尾显示「+N 行」：N 是展开后还看不到的行数，长段落折行出来的行也算。
- 输入区分两层：没在编辑时折叠成一行，只有文字和停止、发送；一编辑（聚焦或有内容）就展开，文字占满整宽，下面一条贴边的工具条，左边是斜杠和附件，右边是模型（下面带上下文条）、停止和发送。折叠时不摆出工具，文字永远不被按钮挤窄。只有点对话、或焦点落到输入区外的另一个控件（且没写内容）才折叠；单纯失去焦点不算。输入区打开的菜单和面板属于输入区，开着时它不折叠——否则菜单会在手指下消失，点到别的项。
- 输入区的按键一个尺寸：桌面 32px、手机 34px，触控区用伪元素扩到 40px；工具键平时只是图标，悬停或打开时才有底色，只有发送键是实心的。模型名和推理强度用紧凑字号与行距排列，为下方上下文条留出空间，不增加按键总高度。
- 上下文和模型有各自的展开操作，但共用原模型键的固定高度：缩小模型名、推理强度的字号与行距，下方放可单独点开的单色上下文条，不另外显示占比文字。小条按真实占比绘制，没有分类色块、最小填充宽度或间距。上下文窗口在手机从底部升起，桌面锚定在条上方；明细滚动区域预留滚动条空间，展开子项不改变内容宽度。占用只算窗口里的内容；按需加载的工具列在「窗口外」，不显示占比。估算值带 ≈，并写明来源和更新时间；分类早于当前总量时写明，条只画总量。没有分类时照常显示总量并说明原因。底部只保留压缩操作，没有接口或命令、正在运行或不可操作时置灰；不单独提供完整计数按钮。

- 手机输入框在普通模式只由外层定位预留一次底部安全区，再留与两侧相同的 9px；单手模式由底部 dock 预留安全区，输入框紧贴 dock（间距不超过 6px）。workbench 内的表单不重复添加安全区，独立浮动输入框仍保留自己的 iOS/Android inset。

- 普通手机顶栏在 420px 以下把 Home、Chat 移入已有侧栏入口，给设备读数、搜索、通知与最右侧头像留出空间；440px 保持原布局。

## 13. 文案

- 中文界面里除产品名、命令名和代码外不出现英文整句；可访问名称与可见文案语言一致。
- 一个概念只用一个名字：线程（Pockymoe 的对话单元）、会话（harness 原生会话，仅用于导入）、Harness（不叫「后端」）、快捷方式（星标，不叫「收藏」）、插话（不写 Steer）、智能体线程。
- 手机上长状态短语改用小图标（带可访问名称）；大块空间放带标签的信息，小块空间不放没有标签的数字。

## 14. 截断

- 文件名在中间省略，保留扩展名和名称末尾几位；统计表的长模型名也使用 `MiddleName`，没有扩展名时保留末尾几位。路径在中间省略，保留第一段和最后一段。树、标签、附件、卡片使用同一规则。
- 被截断的值都能在当前位置读到全文：桌面悬停或聚焦，触屏轻点（卡片）。
- harness 发来的通知、警告等被截成一行的文字，点它就地展开全文，再点收起。
- 标题在手机菜单和底部面板的头部最多两行。

## 15. 设置

偏好类设置改动后立即生效，并就地显示「已保存」；新建对象的表单（连接、价格、工作区）用明确的保存按钮，保存是实色主按钮。离开有未保存修改的表单先询问。

## 16. 点击不留残态

鼠标移开，悬停操作就隐藏；按压结束，强调色和点击背景就复原（用 `:active`）。所有 `:hover` 样式放在 `@media (hover: hover)` 内，避免触屏浏览器把轻点后的悬停效果留在原处；混合悬停、键盘焦点和选中状态的规则要分开，不能让触屏失去后两者。焦点环与聚焦显示的操作只跟随键盘焦点（`:focus-visible`，容器用 `:has(:focus-visible)`），不使用按钮的 `:focus` 或容器的 `:focus-within` 留住点击效果。文字输入可保留输入焦点样式，触屏轻点显示操作只由触摸触发。持续高亮只表示真实的选中、当前或展开状态；轮次订阅以实心铃铛、强调色和提示文字表示，点击背景只在按压时出现。主题包遵守同一规则。

## 17. 滚动条

不出现系统原生滚动条。每个滚动区域都用同一套自绘滚动条：没有箭头和底槽，平时只显示一条很淡的滑块，指针移到该区域时滑块加深，按住时使用主题强调色；外形和颜色由主题决定（经典是细圆条，梅子口袋是圆胶囊加虚线轨，终端是直角方块加细线轨）。只有触屏、没有鼠标或触控板的设备保留系统的悬浮滚动指示：它只在滚动时出现、不占宽度，iOS 也不允许改样式。不要给滚动区域设置 `scrollbar-width: thin` 或 `scrollbar-color`，否则 Chromium 会改回系统滚动条；只有需要隐藏的滚动条才使用 `scrollbar-width: none`。菜单和浮层按内容定尺寸，不出现横向滚动；只有内容超过屏幕时才纵向滚动。

- 设置标签只有整页属于账号级时才加小人标识，并带可访问名称和 `title`「账号设置，所有设备通用」。混有浏览器或设备设置的标签不整体标为账号级；具体控件就地说明保存范围。
