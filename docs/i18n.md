# Web 中英界面

共享 UI 的 `@pockymoe/thread-ui/i18n` 是唯一语言入口。主 Web 在
`src/main.tsx` 初始化并挂载 `I18nProvider`；宿主组件和延迟加载的工作区面板
均订阅同一 store。实现和扩展方式见共享 UI 的 `docs/i18n.md`。

浏览器初次访问根据 navigator languages 识别，明确选择后写入
`remote-codex.locale`，刷新继续使用。英语为 fallback，支持的中文界面为简体。
设置 → 偏好设置提供语言选择；Supervisor 登录、Relay 登录/注册和公开线程
页面也提供入口。语言切换不重建组件或线程，输入草稿保持原文；跨标签页同步。

## 仍保留原文的界面与限制

- Monaco 自带查找/命令面板、Draw.io 内嵌第三方 viewer 的内部控件以及终端进程
  输出不经过我们的产品文案资源；编辑器外层按钮、aria 和文件流程已翻译。
- Harness 传回的模型/能力/技能/MCP 工具名称与描述、插件清单中的自定义名称、
  服务器/第三方原始错误保留原文；本地 UI 错误回退和自己维护的表单校验使用 key。
- 3D 查看器个别 `Atom` 科学工具提示仍为英语。主控件已翻译，坐标、原子元素符号、命令及数值不翻译。
- 已存入状态的瞬时错误/成功提示保持发生时语言；后续操作使用当前语言。
  浏览器已持久化的历史通知同理，避免改写用户记录。Relay worker 收到打开
  页面的语言选择；worker 被系统重启且无打开页面时，推送的无正文回退使用
  浏览器初始语言，服务器提供的推送正文保留原文。
- 此次浏览器验证使用本地 fake Supervisor，覆盖桌面工作台及窄屏设置入口；
  真实 Relay/OAuth/托管 VM/通行密钥服务未端到端启动，相关组件类型和既有回归
  仍检查英语兼容性。没有运行全套 E2E 或 Rust workspace 测试。

## 本地验证

共享 UI JS 修改后先在共享 UI 源仓库构建，再在对应主仓库执行
`pnpm install --offline --frozen-lockfile` 更新 file 依赖，确保 Vite 使用新 dist。
不要直接修改消费方 node_modules 中的产物。

```sh
pnpm --dir pockymoe-thread-ui --filter @pockymoe/thread-ui build
pnpm install --offline --frozen-lockfile
pnpm --dir pockymoe-thread-ui --filter @pockymoe/thread-ui typecheck
pnpm --filter @pockymoe/supervisor-web typecheck
E2E_API_PORT=18182 E2E_WEB_PORT=15182 \
E2E_DATABASE_URL="$PWD/.temp/i18n/e2e.sqlite" \
E2E_WORKSPACE_ROOT="$PWD/.temp/i18n/workspaces" \
pnpm exec playwright test e2e/i18n.spec.ts --project=desktop-chromium
```

Playwright 配置清空继承的正式 `POCKYMOE_*` relay/连接参数，并将
`POCKYMOE_DATABASE_PATH` / `POCKYMOE_WORKSPACE_ROOT` 指向隔离测试路径。

## 帮助页

`/help` 是公开的帮助中心，不需要登录。文章是
`apps/supervisor-web/src/help/<locale>/<topic>.md`（`en`、`zh-CN`），主题列表在
`pages/HelpPage.tsx` 的 `HELP_TOPICS`。二级标题以 `{#anchor}` 结尾，界面用
`/help/<topic>#<anchor>` 链接到具体答案，中英文的锚点必须一致。设备状态标签
（`components/DeviceProtectionStatus.tsx` 的 `protectionView`）链接的每个锚点都必须在
`devices.md` 中存在；`HelpPage.test.tsx` 检查这两点。界面只放一句话的说明，原因和
解决步骤写进帮助页。
